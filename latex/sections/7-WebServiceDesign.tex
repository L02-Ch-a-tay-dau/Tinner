\subsection{Xác thực và Phân quyền}

Hệ thống dùng JWT 2 tầng:
\begin{itemize}
  \item \textbf{Access token} (HS256, mặc định TTL 15 phút) cho mọi request cần xác thực. Mobile lưu trong memory state, gửi qua header \texttt{Authorization: Bearer <token>}.
  \item \textbf{Refresh token} (mặc định TTL 30 ngày) được sinh ngẫu nhiên, lưu hash trong bảng \texttt{refresh\_tokens}. Khi access hết hạn, client gọi \texttt{/auth/refresh} để xoay vòng.
\end{itemize}

\texttt{JwtAuthGuard} đăng ký toàn cục qua \texttt{APP\_GUARD}, áp dụng cho mọi controller mặc định. Để mở public, dùng decorator \texttt{@Public()} (set metadata, guard đọc và bỏ qua) — cấp class hoặc cấp method.

Luồng logout: client gửi refresh token hiện tại tới \texttt{/auth/logout}, backend match hash, xoá record trong DB. Sau đó access token cũ tự hết hạn theo TTL.

\subsection{Validation, Xử lý lỗi và Bảo mật}

\begin{itemize}
  \item \textbf{Validation đầu vào}: DTO kèm \texttt{class-validator}, áp dụng pipeline global \texttt{ValidationPipe} với \texttt{transform: true} (cast string $\to$ number/enum), \texttt{whitelist} (strip field thừa), \texttt{forbidNonWhitelisted} (reject nếu có field lạ).
  \item \textbf{Xử lý lỗi thống nhất}: \texttt{GlobalExceptionFilter} (\texttt{@Catch()}) là middleware bắt tất cả exception. Phân biệt:
    \begin{itemize}
      \item \texttt{HttpException}: trích status + message, validation lỗi → \texttt{message = "Validation failed"}.
      \item Lỗi không lường (Prisma, TypeError, network\ldots): log full stack server-side qua \texttt{Logger}, trả response generic \texttt{500 Internal server error} để không lộ chi tiết nội bộ.
    \end{itemize}
  Trường \texttt{details} (mảng lỗi validation cụ thể) chỉ kèm vào response khi \texttt{NODE\_ENV != "production"} để hỗ trợ developer debug; production luôn giữ message ngắn gọn.
  \item \textbf{Client error format}: mobile client trong \texttt{api.ts} có hàm \texttt{extractErrorMessage} parse JSON response và lấy chỉ \texttt{.message} (fallback "Request failed with status N" nếu body không hợp lệ), tránh hiển thị JSON dump lên UI.
  \item \textbf{CORS}: bật \texttt{credentials} để hỗ trợ cookie/credentials cross-origin từ FE đã được trust.
  \item \textbf{Secrets qua biến môi trường}: \texttt{DATABASE\_URL}, \texttt{JWT\_ACCESS\_SECRET}, \texttt{JWT\_REFRESH\_SECRET}, \texttt{JWT\_ACCESS\_EXPIRES\_IN}, \texttt{JWT\_REFRESH\_EXPIRES\_IN} chỉ inject ở runtime, không commit vào repo.
  \item \textbf{Password storage}: hash bằng \texttt{bcryptjs} (cost 12) trong \texttt{AuthService}.
\end{itemize}

\subsection{Tài liệu hóa API}

Backend tích hợp Swagger/OpenAPI qua \texttt{@nestjs/swagger} và \texttt{swagger-ui-express}. Tài liệu khởi tạo trong \texttt{main.ts} bằng \texttt{DocumentBuilder} với metadata (title, version, description) và \texttt{Bearer Auth} scheme. UI publish tại \texttt{/api/docs}.

Nhờ Swagger, nhóm có thể:
\begin{itemize}
  \item Kiểm thử nhanh endpoint trong browser (paste access token vào ô Authorize).
  \item Đồng bộ contract giữa backend $\leftrightarrow$ mobile mà không cần Postman riêng.
  \item Trong tương lai có thể export OpenAPI spec cho mock server hoặc generate typed client tự động.
\end{itemize}

Hướng nâng cấp tiếp:
\begin{itemize}
  \item Bổ sung đầy đủ \texttt{@ApiTags}, \texttt{@ApiOperation}, \texttt{@ApiResponse} cho từng endpoint.
  \item Chuẩn hoá DTO với annotation Swagger để schema hiển thị chi tiết hơn.
\end{itemize}
